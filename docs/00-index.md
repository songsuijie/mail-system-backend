# Mail System Backend 文档索引

## 1. 文档定位

本目录保存邮件系统后端第一版 MVP 的核心项目文档。后续开发、联调、测试和答辩准备应优先以本目录文档为依据。

当前项目处于后端起步阶段，目标是先完成一个清晰、可运行、可演示的基础邮件系统闭环，再为后续附件、搜索、AI 插件等能力预留扩展空间。

## 2. 当前版本目标

第一版 MVP 聚焦以下主流程：

1. 用户注册并登录系统
2. 登录用户向另一个已存在用户发送邮件
3. 收件人可以在收件箱查看邮件
4. 发件人可以在已发送列表查看邮件
5. 用户可以查看邮件详情
6. 收件人可以标记邮件为已读
7. 收件人可以逻辑删除收件箱邮件

第一版暂不实现真实外部 SMTP、POP3、IMAP 邮件服务器互通，优先实现同一系统内部用户之间的站内邮件收发闭环。

## 3. 必读顺序

开发或修改代码前，建议按以下顺序阅读文档：

1. `AGENTS.md`
   - 项目整体约束
   - Codex 协作规则
   - 推荐目录结构、技术栈和开发优先级

2. `docs/00-index.md`
   - 当前文档入口
   - 文档阅读顺序
   - 各文档职责边界

3. `docs/mvp.md`
   - 第一版 MVP 范围
   - 必做功能、暂不做功能、验收标准

4. `docs/database.md`
   - 数据库表结构设计
   - 表关系、字段含义、约束和扩展点

5. `docs/api.md`
   - 前后端接口契约
   - 请求参数、响应格式、错误码和鉴权约定

6. `docs/git-workflow.md`
   - 分支模型
   - 提交流程
   - commit message 规范

7. `README.md`
   - 项目介绍
   - 本地启动方式
   - 环境配置和运行说明

## 4. 文档职责

| 文档 | 职责 | 维护时机 |
| --- | --- | --- |
| `docs/mvp.md` | 定义第一版功能边界和验收标准 | 功能范围变化时 |
| `docs/database.md` | 定义数据库设计和字段语义 | 表结构变化时 |
| `docs/api.md` | 定义前后端接口契约 | 接口路径、参数、响应变化时 |
| `docs/git-workflow.md` | 定义团队协作和提交规范 | 协作流程变化时 |
| `README.md` | 说明项目如何运行和演示 | 启动方式或环境要求变化时 |
| `sql/schema.sql` | 保存数据库建表 SQL | 数据库结构变化时 |
| `sql/init-data.sql` | 保存初始化测试数据 | 测试数据变化时 |

## 5. 当前事实依据

当前 MVP 范围以 `docs/mvp.md` 为准。

当前数据库设计以 `docs/database.md` 为准；建表 SQL 应维护在 `sql/schema.sql` 中。

当前 API 契约以 `docs/api.md` 为准。

当前 Git 协作规则以 `docs/git-workflow.md` 为准。

如果代码实现与文档不一致，应优先确认是否需要更新文档；不要在未同步文档的情况下静默修改接口或数据库结构。

## 6. 开发优先级

第一阶段优先完成文档和基础设计：

1. 完成 `docs/mvp.md`
2. 完成 `docs/database.md`
3. 完成 `sql/schema.sql`
4. 完成 `docs/api.md`
5. 完成 `README.md`
6. 完成 `docs/git-workflow.md`

第二阶段实现核心后端能力：

1. 用户注册
2. 用户登录和简单 token 鉴权
3. 获取当前用户信息
4. 发送邮件
5. 查询收件箱
6. 查询已发送邮件
7. 查询邮件详情
8. 标记已读
9. 逻辑删除

第三阶段在 MVP 稳定后再考虑可选功能，例如搜索、附件、草稿、垃圾箱、AI 邮件摘要等。

## 7. 变更原则

修改代码时应遵守以下原则：

1. 不随机改变 API 路径、请求字段或响应字段
2. 不随机改变数据库表名、字段名或字段语义
3. 不把业务逻辑直接写在 Controller 中
4. 不在第一版 MVP 中提前引入复杂权限系统、Redis、WebSocket 或 AI SDK
5. 不提交 `target/`、日志、私有配置、临时文件和无关 IDE 文件
6. 涉及 API 或数据库变化时，同步更新对应文档

## 8. 完成标准

一个后端任务完成时，至少应满足：

1. 代码可以编译运行
2. 功能符合 `docs/mvp.md`
3. 接口符合 `docs/api.md`
4. 数据库结构符合 `docs/database.md` 和 `sql/schema.sql`
5. 核心接口可以通过 Apifox 或类似工具测试
6. 相关文档已同步更新
7. 没有引入无关依赖或无关文件变更
