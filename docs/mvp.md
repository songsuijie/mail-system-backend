# 第一版 MVP 功能范围说明

## 1. 文档定位

本文档说明邮件系统后端第一版的开发范围、优先级和验收边界。

当前项目的接口契约以 `docs/api.md` 为最高优先级。若本文档、PRD、数据库文档或 README 与 `docs/api.md` 冲突，以 `docs/api.md` 为准，并同步修改其他文档。

第一版目标不是实现完整企业邮箱，而是先完成一个可运行、可联调、可演示的站内邮件系统。系统不接入真实 SMTP、POP3、IMAP 邮件协议，邮件收发本质上是系统内部用户之间的业务数据流转。

## 2. 优先级定义

`docs/api.md` 将接口分为三类：

| 优先级 | 含义 | MVP 处理方式 |
| --- | --- | --- |
| P0 | 第一阶段必须实现，保证基础邮件闭环可演示 | 必做 |
| P1 | 当前版本推荐实现，支持前端页面完整展示和增强体验 | P0 稳定后优先做 |
| P2 | 可选增强能力，时间充足再做 | 后置 |

开发顺序应先保证 P0 全部跑通，再逐步实现 P1。P2 不应阻塞 P0/P1。

## 3. P0 必做范围

### 3.1 认证模块

必须实现：

- 用户注册：`POST /api/auth/register`
- 用户登录：`POST /api/auth/login`
- 当前登录用户信息：`GET /api/users/me`

说明：

- 登录成功后返回 `token`。
- 后续业务请求通过 `Authorization: Bearer <token>` 传递登录态。
- 第一阶段可以使用简单 token 方案，不强制引入 Spring Security、JWT 或 Redis。
- `POST /api/auth/logout` 在接口清单中属于 P0，但后端实现可选；如果使用简单 token 或 JWT，前端删除本地 token 即可完成退出。

### 3.2 邮件发送

必须实现：

- 发送邮件：`POST /api/mails`

基础规则：

- 当前版本只要求支持单个普通收件人。
- 收件人通过 `recipientUsername` 标识。
- `subject` 和 `content` 不能为空。
- 收件人必须是系统中存在且可用的用户。
- 发送成功后至少创建邮件主体记录和收件关系记录。
- 发送接口返回 `mailId`、发件人、收件人、`sentAt` 和 `analysisStatus` 等字段时，应符合 `docs/api.md`。

### 3.3 邮件列表

必须实现基础列表：

- 收件箱：`GET /api/mails/inbox`
- 已发送：`GET /api/mails/sent`

P0 阶段至少支持：

- 当前登录用户只能查看自己的收件箱和已发送邮件。
- 分页参数 `page`、`size`。
- 返回统一分页结构：`page`、`size`、`total`、`totalPages`、`records`。
- 默认按发送时间倒序。
- 收件箱不展示当前用户已逻辑删除的邮件。
- 收件箱不展示已进入垃圾邮箱的邮件。
- 已发送列表不受收件人删除状态影响。

P1 阶段再补充关键字搜索、筛选、优先级排序和分析字段过滤。

### 3.4 邮件详情

必须实现：

- 邮件详情：`GET /api/mails/{mailId}`

权限规则：

- 发件人可以查看自己发送的邮件。
- 收件人可以查看自己收到的邮件。
- 其他用户不能查看该邮件，应返回 `40003`。

自动已读规则：

- 根据 `docs/api.md`，如果当前用户是收件人，且邮件原本未读，调用详情接口后应自动标记为已读。
- `PATCH /api/mails/{mailId}/read` 仍需要实现，用于显式标记已读。

### 3.5 邮件状态

必须实现：

- 标记已读：`PATCH /api/mails/{mailId}/read`
- 逻辑删除：`DELETE /api/mails/{mailId}`

规则：

- 只有收件人可以修改自己的已读状态。
- 发件人不能修改收件人的已读状态。
- 当前版本删除只针对收件人侧状态。
- 删除后邮件不再出现在普通收件箱或垃圾邮箱中。
- 删除后邮件应出现在已删除列表；已删除列表接口为 P1。

## 4. P1 推荐范围

P1 用于让前端页面更完整，建议在 P0 跑通后实现。

推荐实现：

- 搜索用户：`GET /api/users/search`
- 用户设置和 AI 配置状态：`GET /api/users/settings`
- 更新用户设置和 AI 配置：`PUT /api/users/settings`
- 已删除列表：`GET /api/mails/trash`
- 垃圾邮箱列表：`GET /api/mails/spam`
- 邮箱统计数量：`GET /api/mails/statistics`
- 收件箱、已发送、已删除、垃圾邮箱的搜索与过滤参数
- 邮件列表和详情中的分析字段

P1 搜索与过滤范围以 `docs/api.md` 第 17 节为准。

## 5. P2 后置范围

P2 可选实现：

- 修改密码：`PUT /api/users/password`
- 恢复已删除邮件：`PATCH /api/mails/{mailId}/restore`
- 重新分析邮件：`POST /api/mails/{mailId}/analysis/retry`

P2 不应阻塞 P0/P1 的开发、联调和演示。

## 6. AI 与分析能力边界

当前接口文档已经包含分析字段、用户 AI 设置和邮件分析结果，但 AI 能力必须作为增强能力处理。

规则：

- 基础邮件发送、收件、查看详情、删除等主流程不能依赖 AI 成功。
- 发送邮件后可以同步或异步生成分析结果。
- 如果用户关闭 AI、模型未配置、调用失败或解析失败，应降级为规则或本地分析结果。
- 不单独提供测试 AI 连接接口。
- 不提供 AI 服务商列表接口。
- 不实现流式输出、AI thinking 展示、Claude 原生协议适配或多模型配置。

第一版可以先使用规则生成默认分析结果，保证接口字段完整，再逐步接入真实模型调用。

## 7. 统一响应和时间格式

所有接口遵循 `docs/api.md`：

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

失败响应：

```json
{
  "code": 40001,
  "message": "用户名或密码错误",
  "data": null
}
```

时间格式统一返回 ISO 8601 字符串，例如：

```text
2026-05-25T16:04:00
```

## 8. 验收流程

P0 验收建议：

1. 注册用户 A。
2. 注册用户 B。
3. 用户 A 登录。
4. 用户 A 发送邮件给用户 B。
5. 用户 A 查看已发送列表。
6. 用户 B 登录。
7. 用户 B 查看收件箱。
8. 用户 B 查看邮件详情，详情接口自动标记已读。
9. 第三方用户尝试查看该邮件详情，应返回无权限。
10. 用户 B 调用标记已读接口。
11. 用户 B 删除邮件。
12. 用户 B 再查收件箱，该邮件不再出现。

P1 验收建议：

1. 用户 B 查看已删除列表，该邮件出现。
2. 查询邮箱统计数量。
3. 测试收件箱关键字搜索和未读筛选。
4. 测试垃圾邮箱列表。
5. 测试用户设置读取和更新。

## 9. 非当前范围

以下能力当前不做或后置：

- SMTP、POP3、IMAP 接入。
- 附件上传、下载和预览。
- 多收件人、CC、BCC。
- 草稿箱。
- 邮件撤回。
- WebSocket 实时通知。
- 管理员后台。
- 复杂角色权限系统。
- 全文搜索引擎或语义搜索。
- 流式 AI 输出。
- 多模型配置。
